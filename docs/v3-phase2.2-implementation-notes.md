## 修改的既有測試與原因

- `test_workflow_repair.py`：來源別名仍可讀取，但模擬來源依實際參數取得方式決定，不由舊文字標籤改寫；原有參數與求解檢查保留。
- `optimizer.spec.ts`：中文選取器、動態溶劑欄位；需要示範資料的案例改為明確載入。
- `p0-estimation.spec.ts`：來源徽章改文字，CSV 增加中文來源欄，條件差異訊息改中文；手動與校正保護、延遲回應測試保留。
- `retention-integration.spec.ts`：移除來源選單操作，舊曲線範例改用相同 API 範例作測試初始資料；相同化合物若查得到曲線，依新優先順序顯示實測曲線；手動保護保留。
- `v2.spec.ts`：方法專屬模型改檢查唯讀資料庫及模型登錄，原有後端方法限制測試保留；UV 匯入匯出僅調整顯示文字。
- `workbench.spec.ts`：明確載入示範、中文標籤與錯誤提示；既有模擬、最佳化及重新整理流程保留。
- `workflow-repair.spec.ts`：舊校正工作流程遷移為共用流程，使用新備份鍵；來源選單改查不存在；重設後明確載入示範。
- `fixtures.ts`：提供舊曲線範例與相同來源條件的測試初始資料，保留原有請求節流。

新增 `test_presentation.py` 檢查訊息、代碼、來源優先保護及字典同步；新增 `zh-tw.spec.ts` 檢查空白專案、示範、名稱、徽章、匯出、改名、溶劑標籤及可見文字。
